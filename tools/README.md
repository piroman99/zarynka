# tools/ — рабочие скрипты проекта

Здесь всё, что раньше лежало в корне репозитория (2026-11-22: корень был 1125
скриптов, стало 0). Раскладка плоская не по неаккуратности: скрипты импортируют
друг друга по имени (`import pv`, `import _vn2_nodes`, `import _cdp`), а при
плоском каталоге эти импорты продолжают работать.

## Как запускать

Из корня репозитория:

```bash
python3 tools/_vn2_build.py           # собрать vn2/content.js из story.txt
python3 tools/_vn2_nodes.py           # индексы узлов (печатает карту)
python3 tools/_pl_regress.py          # регресс предзагрузки
```

Внутри скрипта пути считаются от каталога репозитория:

```python
HERE = os.path.dirname(os.path.abspath(__file__))   # tools/
ROOT = os.path.dirname(HERE)                        # корень репо
```

Всё, что относится к репозиторию (`assets/`, `vn2/`, `out/`, `_sat/`), берётся
через `ROOT`, поэтому скрипты работают из любого каталога запуска.

## Подкаталоги

| каталог | что там |
|---|---|
| `alley/` | сцена «аллея у ворот»: скамейка в Blender, акварельный фильтр, посадка поэта, дефринж спрайтов |
| `scratch/` | одноразовые скрипты-пробы (575 шт.): никто их не вызывает, в пайплайне они не участвуют. Импортировать общие модули (`pv`, `_cdp`) они умеют через `ROOT/tools` |

## Проверка после переноса

`tools/_verify_after_move.py` — компилирует все файлы, проверяет, что каждый
`os.path.join(ROOT, '…')` указывает на существующий путь, импортирует общие
модули и прогоняет один живой скрипт. Результат 2026-11-22: 1138 файлов
компилируются, битых путей 0, `pv`/`_vn2_nodes`/`_move_tools` импортируются,
`alley/_poet_measure.py` даёт те же числа, что до переноса.

## Если понадобился скрипт из `scratch/`

Он писался под старую раскладку (пути от `HERE`), поэтому перед запуском
проверьте `ROOT`-пути и `sys.path` — либо перенесите его в `tools/`:

```bash
python3 tools/_move_tools.py tools scratch/_имя.py
```
